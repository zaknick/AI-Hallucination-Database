# Contributing

Thank you for helping expand the AI Hallucination Database.

This repository uses a standardized case structure so that evaluations remain consistent, reviewable, and suitable for later dataset analysis.

---

## Adding a New Case

Create each new case inside the root-level `cases/` directory.

Use this naming format:

```text
prompt-###-short-description/
```

Example:

```text
prompt-002-fabricated-court-case/
```

Use:

- a three-digit prompt number;
- lowercase letters;
- hyphens instead of spaces;
- a short description of the test.

---

## Required Case Structure

Every case must use the following structure:

```text
cases/
└── prompt-###-short-description/
    ├── README.md
    ├── prompt.md
    ├── assessment.md
    ├── responses/
    │   ├── chatgpt.md
    │   ├── claude.md
    │   └── gemini.md
    └── evidence/
        ├── sources.md
        └── screenshots/
            ├── README.md
            ├── chatgpt-response.jpg
            ├── claude-response.jpg
            └── gemini-response.jpg
```

Additional model-response and screenshot files may be added when other providers are evaluated.

Use lowercase filenames and hyphens where needed.

---

## Case README

The case-level `README.md` should provide a concise overview of the completed evaluation.

It should include:

- prompt ID;
- category;
- domain;
- primary behavior tested;
- test date;
- models evaluated;
- score summary;
- key findings;
- hallucination categories observed;
- links to all case files;
- and the most important comparative finding.

The case README should summarize the evaluation rather than duplicate the full assessment.

---

## Prompt File

The `prompt.md` file should preserve the exact test prompt.

It should include:

- prompt ID;
- category;
- domain;
- primary behavior tested;
- the prompt reproduced verbatim;
- and a preservation note.

Do not include:

- model responses;
- evaluator findings;
- correct information;
- evidence;
- or model scores.

---

## Response Files

Each model response must be stored in a separate file inside `responses/`.

Required files:

```text
responses/
├── chatgpt.md
├── claude.md
└── gemini.md
```

Each response file should include:

- provider;
- displayed model;
- test date;
- browser;
- whether search or browsing was used;
- a capture note when needed;
- the full response;
- and sources cited by the model.

Preserve the response as closely as possible to the original output.

Do not silently correct:

- factual errors;
- spelling mistakes generated by the model;
- incorrect dates;
- incorrect names;
- fabricated citations;
- fake URLs;
- misleading wording;
- or unsupported claims.

Formatting may be adjusted for readable Markdown when copy-and-paste limitations, citation chips, source cards, or interface behavior prevent exact preservation.

Any such formatting limitation should be disclosed in a capture note.

---

## Screenshot Requirements

Screenshots should be stored inside:

```text
evidence/screenshots/
```

Standard filenames are:

```text
chatgpt-response.jpg
claude-response.jpg
gemini-response.jpg
```

The screenshots directory must contain a `README.md` that:

- identifies each provider and displayed model;
- records the test date, browser, and search status;
- embeds each screenshot;
- links to the corresponding transcribed response;
- and explains any capture or formatting limitations.

Screenshots should be preserved as collected.

Do not add factual corrections, annotations, or altered text to the original images.

When a response requires multiple screenshots, use numbered filenames:

```text
chatgpt-response-01.jpg
chatgpt-response-02.jpg
```

---

## Assessment Requirements

The full evaluation belongs in `assessment.md`.

Apply the scoring system defined in the root-level [`RUBRIC.md`](RUBRIC.md).

Each model evaluation must include:

- provider;
- displayed model;
- search or browsing status;
- outcome;
- hallucination category or categories;
- hallucination findings;
- correct information;
- evidence analysis;
- Factual Accuracy score;
- Evidence Support score;
- Citation Quality score;
- Confidence Calibration score;
- Performance Score;
- Hallucination Severity;
- and Evaluator Notes.

The assessment must also include:

- test information;
- the original prompt;
- ground truth;
- evaluator evidence;
- a score-summary table;
- and a comparative conclusion.

Hallucination severity is scored separately and must not be added to the performance score.

---

## Evidence File

Evaluator sources belong in:

```text
evidence/sources.md
```

This file must remain separate from sources cited by the models.

For every evaluator source, record:

- institution or publisher;
- title;
- source type;
- URL;
- access date;
- claims the source was used to verify;
- supported facts;
- evaluation relevance;
- and any evidentiary limitations.

When appropriate, include a verification matrix connecting evaluated claims to their supporting sources.

---

## Evidence Standards

Preferred sources are:

1. Official government records
2. Primary documents
3. Academic publications
4. Reputable institutional sources
5. High-quality secondary sources

Official or primary sources should be used whenever available.

Do not rely on another AI response as evidence.

Do not treat a search-result snippet as sufficient evidence when the underlying source can be opened and reviewed.

Disclose:

- uncertainty;
- incomplete records;
- conflicting sources;
- database limitations;
- inaccessible archives;
- and reliance on secondary reproductions.

---

## Scoring Consistency

All evaluations must follow the repository-wide rubric.

Do not:

- invent new scoring categories for an individual case;
- combine severity with the performance score;
- change scoring direction;
- or assign scores without written justification.

Scores in the following files must agree:

- case `README.md`;
- `assessment.md`;
- and root `index.csv`.

---

## Updating index.csv

Each evaluated model should receive one row in the root-level `index.csv`.

Every row should include:

- prompt ID;
- case slug;
- case title;
- category;
- domain;
- test date;
- provider;
- displayed model;
- search status;
- four performance-criterion scores;
- total performance score;
- severity;
- outcome;
- hallucination categories;
- case status;
- and case path.

Use semicolons inside a CSV field when listing multiple hallucination categories.

Do not use commas inside an unquoted field.

---

## Quality-Control Checklist

Before marking a case complete, confirm that:

- every required file exists;
- all links work;
- all screenshots display correctly;
- model names and dates are consistent;
- response files preserve the collected outputs;
- evaluator sources are separate from model citations;
- every factual correction has supporting evidence;
- rubric scores are justified;
- score totals are mathematically correct;
- severity is reported separately;
- the case README matches the full assessment;
- and `index.csv` contains the corresponding model rows.

---

## Pull Requests

Each pull request should add or modify one case whenever practical.

The pull-request description should explain:

- what was added or changed;
- which sources were used;
- whether any uncertainty remains;
- and whether the root index was updated.

Avoid combining unrelated case changes in the same pull request.
